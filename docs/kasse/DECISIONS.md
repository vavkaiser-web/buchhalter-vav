# Касса VAV — решения по архитектуре

## D-01: Автономный сервер, не расширение Buchhalter
**Решение:** kasse-vav запускается как отдельный процесс на порту 3127.
**Почему:** Buchhalter имеет собственную логику и маршруты. Смешение создаст зависимость релизов.
**Компромисс:** Общая БД (mailops_prod), общий формат benutzer.json. Пользователи синхронизируются через общий файл.

## D-02: Дизайн из approved-design.html — дословно
**Решение:** CSS vars из approved-design.html скопированы без изменений.
**Почему:** Задание требует точного соответствия утверждённому макету.
**MD5 CSS:** 75cf11c8e42de979bd6ec8c56e660846

## D-03: HMAC-сессия, не JWT
**Решение:** `timestamp.base64(login).hmac[:32]` в cookie `kassesess` (30 дней).
**Почему:** Нет внешних зависимостей (только `crypto`). Сессии revocable через смену SECRET.
**SSO:** Принимает также `vavsess` от vavapp (читает тот же секрет через `KASSE_SECRET` или общий SECRET файл).

## D-04: Файловые пользователи (benutzer.json)
**Решение:** Пользователи хранятся в benutzer.json (scrypt + соль).
**Почему:** Единый источник данных с Buchhalter, нет дублирования схемы БД для аутентификации.
**Роли допустимые в Кассе:** gf, buchhaltung, disponent, mitarbeiter. Роль `buero` → 403.

## D-05: Идемпотентная очередь событий
**Решение:** `ereignis_id` (UUID) — ключ идемпотентности. `ON CONFLICT DO NOTHING`.
**Почему:** HTTP-retry и сетевые сбои не должны приводить к двойным транзакциям.
**Retry:** Экспоненциальный backoff, max 6 попыток, после — status=FEHLER.

## D-06: 7 состояний жизненного цикла
ENTWURF → EMPFANGEN → PRUEFEN → KLAEREN → (ABGELEHNT | BEWILLIGT → AUSGEGEBEN)
**Почему:** KLAEREN необходим для цикла вопрос-ответ между бухгалтером и сотрудником без потери истории.

## D-07: Корневые ресурсы (иконки, vendor) доступны с root path
**Решение:** Добавлен маршрут `/icon-*.png`, `/vendor/*`, `/manifest.webmanifest` в kasse-server.js.
**Почему:** SW пытается кэшировать `/icon-192.png` и `/vendor/lucide.min.js` при install, должны быть доступны.
