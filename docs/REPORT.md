## Что реально работает (сервер + права + база)
- **Наличные:** заявка со списком → отдельная квитанция на каждого получателя → утверждает только Андрей → выдача (только она двигает деньги). Снятие в банке отмечает Андрей; получатель подтверждает получение сам, передающий подтвердить за него не может. Деньги у Олега — отдельный счёт; возврат в кассу подтверждает бухгалтер. Остаток — «расчётный», пересчёт — «Не подтверждён».
- **Срочная выдача Олегом** — только аванс/зарплата, в пределах остатка, квитанция сразу; рабочим подрядчика — только по утверждённому списку (право не согласовано).
- **Печатный бланк квитанции** (одна квитанция — одна страница; весь список заявки): номер, получатель, подрядчик, сумма, назначение, даты, места подписи, явный статус («подготовлена — деньги НЕ выдавать» / «выдана …»).
- **Чеки:** рабочий фотографирует и отправляет; машина на каждом чеке, канистра/техника; объект для материалов. Бухгалтер проверяет; свой расход проверяет Андрей. Отклонение не возвращает деньги в остаток. Чек из аванса — не второй расход. Проверенный чек ≠ выплаченное возмещение: наличными через Олега без Андрея, переводом — Олег согласует, Андрей отмечает перевод.
- **Запросы:** сотрудник 2 рабочих дня → Олег 1 → Андрей (рабочие дни Баварии/Нюрнберга); потерянный чек — сразу бухгалтеру и Андрею; ответ не закрывает вопрос — закрывает бухгалтер с записью проверки. Уведомления никому не отправляются (канал не согласован).
- **Подрядчик:** один счёт — один комплект; полная сумма работ не уменьшается, выданные квитанции уменьшают только остаток к оплате; повторный и сверхсуммовый зачёт невозможен, остаток квитанции хранится; нужны подтверждение Олега, подписи, подтверждение подрядчика, проверка бухгалтера → «Передать Андрею». Андрей отмечает «перевод внесён в банке»; приложение денег не переводит. Реквизиты — только с указанным источником и проверкой IBAN, иначе «Не указаны».
- **Банк:** FinMap только читается. Связь операции с документом — только если операция найдена, это расход и сумма совпала; расхождение — только явно с пояснением и не считается подтверждением. Полной банковской сверки нет.
- **Надёжность:** деньги в центах; блокировки и проверка остатка; ключи повтора (двойное нажатие, обрыв сети); один файл — один чек даже параллельно; журнал автора и времени, удаление запрещено.
- **Телефон без сети:** фото и чек сохраняются на телефоне (очередь), экран открывается без сети, после появления связи чек уходит один раз. Черновик и очередь — отдельно для каждого входа; если на общем телефоне вошёл другой человек, чужой чек не отправляется.
- Классические разделы Бухгалтера сохранены без изменений по адресу `/`; новые роли туда не пускаются.

3. «Документ читается, сумма совпадает» — пустой кружок до приёмки чека бухгалтером (система не распознаёт чек и не должна это утверждать); «Повторного чека не найдено» — реальная проверка.

## Ограничения и открытые решения (не реализовано намеренно)
- Налоговые блокировки, Kontenrahmen, DATEV, закрытие месяца, расчёт доступной зарплаты — не включены.
- Каналы уведомлений не согласованы — ничего не отправляется.
- Как входят сотрудники (свои ПИНы или вход из Учёта часов) — открыто; сейчас свои входы Бухгалтера с привязкой к человеку из Учёта часов.
- Порядок физического пересчёта, частичная оплата спорного счёта, распределение чека на несколько объектов, импорт банковской выписки, Vimcar — открыто.
- Роль «офис» к кассе не допущена (не согласовано).
- Реквизиты подрядчиков: проверенного источника в базе нет — вносятся вручную с указанием источника.
- Офлайн-очередь сделана для чеков сотрудника; остальные действия без сети не выполняются (сообщение об этом честное).
- Пульт: сообщение №11 «Дата старта» в статусе «Обсуждаем» — эта работа дату старта не меняет.
